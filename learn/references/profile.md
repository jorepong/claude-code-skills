# 학습 프로필 — 읽기·쓰기·부재 시 처리

학습자의 특성과 지식 수준은 **전역 원본 `~/.claude/profile/LEARNING_PROFILE.md`** 하나로 관리한다. 이 스킬은 특정 프로젝트의 프로필을 만들거나 읽지 않는다 — 언제나 이 전역 파일이 대상이다.

이 파일은 두 가지 목적을 동시에 가진다:
1. **설명 조율 기준**: 학습 자료를 만들고 설명 수준·강조점을 조절할 때, 그리고 점수를 매길 때 참조한다.
2. **지식 베이스**: 이 사람이 무엇을 할 수 있는지를 외부인도 파악할 수 있는 문서다.

## 프로필이 없거나 비어 있을 때 (일반 수준)

전역 파일이 없거나 사실상 비어 있으면:
- **온보딩하지 않는다.** 무엇을 배우고 싶은지 이상으로 배경을 캐묻지 않는다.
- **일반적인 유능한 개발자 수준**을 기본값으로 삼아 설명한다(너무 기초로 내려가지도, 특정 고급 배경을 가정하지도 않는다).
- **점수(추천/장악 점수)를 표시하지 않는다.** 점수는 "이 학습자가 지금 이걸 배워야 하는 정도"라, 프로필이라는 근거 없이는 의미가 없다. 개요를 만들더라도 포인트를 점수 없이 나열한다.
- 학습 중 지속적 특성이 뚜렷이 관찰되면, 세션 끝에 **전역 프로필을 새로 만들지 짧게 제안**할 수 있다(강제하지 않는다). 사용자가 원할 때만 아래 구조로 생성한다.

## 프로필로 무엇을 하는가

- **이해 수준·효과적인 설명 방식** → 설명의 깊이·진입점·골격을 정한다(`explanation-principles.md`의 '설명을 이 학습자에게 맞춰 설계한다').
- **지식 베이스(역량 / `학습 중` / `부족한 영역`)** → **점수**를 정한다. 점수가 답하는 질문은 "이 개념/유닛이 구현에서 얼마나 중요한가"가 아니라 **"이 학습자가 그것과 어떤 관계에 있길래 지금 배워야 하는가"**다. 역량 가장자리(새롭고 지금 닿는 것)나 메워야 할 토대(그 수준이면 이미 알았어야 하는데 빈 것)는 높고, 이미 자율적으로 하는 것은 낮다. 밴드 표는 각 트랙 레퍼런스(`concept-learning.md`·`implementation-mastery.md`)에 있다.
- 분류(핵심/보조)와 점수는 **다른 축**이다 — 분류는 '이 흐름을 따라가는 데 중심적인가', 점수는 '이 학습자에게 지금 필요한가'. 자주 어긋나며, 어긋나는 게 맞다.

## CodeLayer 용어를 프로필에 쓰지 않는다

프로필은 특정 프로젝트에도, 이 학습 구조에도 종속되지 않는다. 이 시스템을 처음 보는 사람도 읽고 이해할 수 있도록 **사람 자체**에 대한 정보만 담는다. 서술에 이 시스템의 개념·구조(코드 앵커, 섹션, 개요 문서, 학습 단계, 구현 유닛, 관전 문서 등)가 등장해서는 안 되고, 이 시스템의 동작 방식을 알아야만 해석되는 표현도 쓰지 않는다.

```
나쁜 예: "멀티스텝 흐름을 단계별로 스스로 서술하는 능력이 나타나기 시작함"
         → '멀티스텝 흐름'·'단계별 서술'이 이 학습 구조를 전제함
좋은 예: "복잡한 개념을 구성 요소로 분해하고 인과 순서대로 설명하는 능력이 있음"
         → 이 시스템을 모르는 사람도 읽고 이해할 수 있음
```

## 구조

```markdown
# 학습자 프로필

## 기술 배경
[주력 언어/스택, 경력, 현재 학습 중인 영역]

## 이해 수준
[추상적 설명 소화력, 새 패턴 흡수 속도, 독립 추론 가능한 수준]

## 효과적인 설명 방식
[어떤 접근이 잘 맞는지 — Why First, 비유, 코드 우선 등]

## 지식 베이스
[기술 도메인별로 역량(무엇을 얼마나 자율적으로 할 수 있는가), 학습 중인 영역, 부족한 영역을 서술]
```

**지식 베이스는 개념 목록이 아니라 역량 서술이다.** 외부인이 "이 사람은 이 기술로 무엇을 할 수 있겠다"고 추정할 수 있어야 한다. "EAGER/LAZY 로딩을 안다"처럼 아는 개념을 나열하지 말고, 그것을 통해 드러나는 **역량의 범위와 자율성**으로 표현한다. 각 도메인 항목은 세 요소로 구성된다 — **역량**(어떤 수준의 문제를 얼마나 자율적으로 다루는가, 필수), **학습 중**(아직 완전히 소화되지 않은 것, 해당 시), **부족한 영역**(인식하는 갭, 해당 시). 구현 장악에서 관찰되는 **절차적 자율도**("이 흐름을 백지에서 설계·구현·배선할 수 있는가")도 별도 축이 아니라 역량 서술의 자율성에 녹인다.

## 갱신 동작 — 모든 섹션에 공통

이 원칙은 네 섹션(기술 배경 · 이해 수준 · 효과적인 설명 방식 · 지식 베이스) 전부에 같은 방식으로 적용된다.

갱신의 본질은 하나다. **매번 그 항목을, 지금 처음 쓰는 것처럼, 이 사람의 현재 상태를 가장 잘 드러내도록 다시 쓴다.** 기존 서술에 새 줄을 덧붙이는 것이 아니라, 새로 알게 된 것까지 포함해 그 사람의 지금을 다시 그려낸다. 아래는 이 하나의 동작에서 따라 나오는 결과다.

- **과거의 서술은 출발점이 아니라 참고 자료다.** 다시 쓰는 것이므로 이전 문장을 보존할 의무가 없다. 새 관찰이 기존 표현을 더 정확하게 만들면, 이전의 좁거나 조심스러운 표현은 미련 없이 덮어쓴다. 옛 문장과 새 문장이 나란히 남는 일은 없다.
- **분량은 목표가 아니라 결과다.** "현재 상태를 가장 잘 드러낸다"는 목적에 필요한 만큼 쓴다. 역량이 좁으면 짧고 넓어지면 길어진다. 상한은 글자 수가 아니라 **읽는 사람**이 정한다 — 제3자가 그 항목만 읽고 "무엇을 어디까지 할 수 있는지" 파악하면서도 부담되지 않는 지점.
- **서술의 형태를 미리 정하지 않는다.** 개념을 짚어 나열할지, 하나로 묶어 포괄할지는 무엇이 현재를 더 선명하게 드러내느냐로 그때그때 정해진다.
- **담을 것과 버릴 것은 지속성으로 가른다.** 세션이 바뀌면 이전 대화를 기억하지 못하므로 "몇 번 봤는지"로 판단하지 않는다. 이번에 본 것이 그 사람을 설명하는 지속적 특성이면 담고, 그 순간의 우연한 반응이면 담지 않는다. 매번 전체를 다시 쓰므로, 한때 담겼던 것도 지금의 그 사람과 맞지 않으면 다음 집필에서 자연히 빠진다.

## 업데이트 시점

학습이 끝날 때 — 특히 이해도·장악 평가 직후(평가를 건너뛴 경우 포함) — 네 섹션 전부에 대해 갱신이 필요한지 판단한다. 평가했다면 평가 결과를, 건너뛰었다면 학습 과정에서 관찰된 것(질문 방식, 이해 속도, 반응, 스스로 설계·구현·검증한 정도)을 근거로 판단한다.

- **기술 배경 / 이해 수준 / 효과적인 설명 방식**: 새로운 지속적 특성이 관찰됐을 때, 또는 기존 서술이 지금 관찰과 더 이상 맞지 않을 때.
- **지식 베이스**: 역량의 범위·자율성이 실질적으로 확장됐을 때, 새 기술 도메인이 처음 등장했을 때, 또는 `학습 중`·`부족한 영역`의 상태가 달라졌을 때.

그렇지 않다면 — 이번 학습이 기존 서술에 이미 충분히 담겨 있다면 — 갱신하지 않는다. 갱신했다면 채팅에 한 줄 알린다:
> "프로필을 갱신했습니다. [변경 내용 한 줄 요약]"

갱신 사항이 없으면 알리지 않는다. **갱신 여부를 구두로 예고하거나 다음으로 미루지 않는다** — 판단 즉시 파일을 고친다.
