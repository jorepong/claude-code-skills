# 작업 공간·레이아웃·학습 강도

## 전역 학습 아카이브

학습 산출물의 기본 위치는 **`~/.claude/learn/<YYYY-MM-DD>-<슬러그>/`**다. 날짜가 폴더명의 맨 앞에 오므로 파일 목록이 학습 시작일 순서로 정렬된다. 한 번의 `/learn`은 한 주제를 다루고 그 폴더 안에서 완결된다.

- **재지정.** 학습자가 현재 디렉토리나 특정 경로를 원하면 그 경로 아래에 `<YYYY-MM-DD>-<슬러그>/`를 만든다. 경로를 재지정해도 날짜 접두사를 생략하지 않는다.
- **날짜.** 실행 환경의 로컬 날짜를 `YYYY-MM-DD`로 사용한다. 셸에서는 `date +%F`로 구하며 UTC 날짜를 따로 계산하지 않는다. 예: 2026년 8월 31일 + `kafka-consumer-groups` → `2026-08-31-kafka-consumer-groups`.
- **슬러그.** 주제를 소문자·하이픈, 비ASCII 지양 식별자로 정규화한다(`카프카 컨슈머 그룹` → `kafka-consumer-groups`). 같은 날짜의 같은 폴더가 이미 있으면 이어 쓰되 덮어쓰기 전에 확인한다. 사용자가 명시적으로 예전 학습을 이어 달라고 하면 `????-??-??-<슬러그>` 중 해당 폴더를 찾아 기존 날짜를 유지한다. 그 외에는 날짜가 달라질 때 새 폴더를 만든다.
- 폴더는 `mkdir -p`로 만든다. 학습자의 프로필 원본(`~/.claude/profile/LEARNING_PROFILE.md`)은 이 아카이브 밖에 있고 이 스킬이 함부로 건드리지 않는다(갱신은 `profile.md` 규율에 따라서만).

## 산출물 레이아웃

**무겁게 모드 (완전판):**

```
~/.claude/learn/pronunciation.md   # 낭독 발음 사전 — 주제 폴더 밖, 모든 주제 공용·누적
~/.claude/learn/<YYYY-MM-DD>-<슬러그>/ # 한 학습 실행 (날짜가 항상 맨 앞)
├── overview.md                    # 점수 통합 개요 — [N] 개념 · [U N] 구현 유닛
├── <포인트-슬러그>/               # 개념 학습 문서 (개념 포인트마다 한 폴더)
│   ├── 01-<코드요소명>.md
│   ├── 01-<코드요소명>.script.md  # 동반 낭독 스크립트(문서마다 짝, 항상)
│   ├── 02-<코드요소명>.md
│   ├── 02-<코드요소명>.script.md
│   ├── audio/                     # narrate.sh 렌더 음성(01.mp3 …)
│   ├── 01-<코드요소명>.player.html # 즉시 읽기 가능; 좌측에 현재 모든 챕터, 렌더 뒤 같은 파일에 음성 결합
│   ├── assets/                    # 정적·동적 시각 자료와 주제 번들
│   └── exercises/
│       ├── Q01-<질문주제>.md
│       └── Ex01-<과제명>.md
├── <선행-슬러그>/                 # 선행 학습 개념 폴더 ([P1] 선택 시)
│   └── 01-….md
└── mastery/                       # 구현 장악 (실습형 주제일 때만)
    ├── reference-impl/            # 스킬이 지은 참조 구현(정답지·원본 보존)
    ├── journal.md                 # 그 제작 궤적의 날것 일지(관전 문서 원재료)
    ├── 01-<관전제목>.md           # 시간·의존 순서의 관전 문서(주제당 한 벌)
    ├── assets/
    └── exercises/                 # 장악 평가(생성·검증), 고른 유닛별
        ├── Ex01-<유닛명>-재구성.md
        └── Q01-<유닛명>-방어인출.md
```

**가볍게 모드 (평평하게):** 개요·번호 없이 주제 루트에 섹션 문서만 둔다.

```
~/.claude/learn/<YYYY-MM-DD>-<슬러그>/
├── 01-<섹션>.md
├── 01-<섹션>.script.md   # 동반 낭독 스크립트(항상)
├── 02-<섹션>.md
├── 02-<섹션>.script.md
├── audio/                # narrate.sh 렌더 음성
├── 01-<섹션>.player.html  # 즉시 읽기 가능; 좌측에 현재 모든 챕터
└── assets/               # 필요 시
```

### 파일명 규칙

| 경로 | 규칙 | 예시 |
|------|------|------|
| `overview.md` | 주제당 하나 — 개념·유닛 통합 | `overview.md` |
| `<포인트-슬러그>/` | `NN-<코드요소명>.md` | `02-resolveToken.md` |
| 낭독 스크립트 | `NN-<코드요소명>.script.md` (문서와 같은 `NN`으로 짝) | `02-resolveToken.script.md` |
| 낭독 음성·플레이어 | `audio/NN.mp3` · `<NN-슬러그>.player.html` (`build-players.sh`가 먼저 만들고 `narrate.sh`가 음성을 결합) | `audio/02.mp3` |
| `<포인트-슬러그>/exercises/` | `Ex[N]-<과제명>.md` (안내+스켈레톤 포인터) / `Q[N]-<질문주제>.md` | `Ex01-복합키구현.md` |
| `mastery/` | `NN-<제목>.md` (관전 문서, 조각 경계를 가로지름) | `01-무엇이-어디로-흐르나.md` |
| `mastery/exercises/` | `Ex[N]-<유닛명>.md` · `Q[N]-<주제>.md` (고른 유닛별) | `Ex01-흐름조립-재구성.md` |
| 시각 이미지 | 그 문서 폴더 아래 `assets/`, 상대경로 임베드 | `assets/token-bucket.svg` |
| 애니메이션 포스터 | `assets/<컴포지션>.anim.poster.svg` — player가 이 자리를 Remotion Player로 승격 | `assets/EventLoop.anim.poster.svg` |
| 시뮬레이션 포스터 | `assets/<이름>.sim.poster.svg` — player가 이 자리를 React 시뮬레이션으로 승격 | `assets/PacketLossLab.sim.poster.svg` |
| 동적 시각 번들 | `assets/anim.bundle.js` — 애니메이션·시뮬레이션을 `.remotion/build.sh <날짜-주제-슬러그> <문서 폴더>`가 함께 생성 | `assets/anim.bundle.js` |

- N/NN은 두 자리(`01`, `02`, …). 포인트-슬러그·유닛명은 개요에 기재한 이름과 일치시킨다.
- 가볍게 모드나 단일 포인트 주제는 `<포인트-슬러그>/` 없이 주제 루트에 평평하게 둬도 된다 — 판단.

## 동적 시각 작업 공간

Remotion 애니메이션과 React 시뮬레이션의 소스는 주제 폴더가 아니라 **공용 작업 공간 `~/.claude/learn/.remotion/`**에 둔다. `src/<YYYY-MM-DD>-<주제-슬러그>/`에 컴포넌트와 `index.jsx`, 공용 등록 런타임은 `src/lib/register.jsx`, 번들은 `build.sh`다. 날짜가 다른 같은 주제의 자산이 충돌하지 않게 동적 시각 식별자도 산출물 폴더명과 맞춘다. 작법은 `animation.md`와 `simulation.md`를 따른다.

## overview.md 구조 (무겁게 모드)

세 파트로 구성한다 — **학습 여정**(파트 1), **개념 학습 포인트**(파트 2, `[N]`·추천 점수), **구현 유닛**(파트 3, `[U N]`·장악 점수). 맨 위 요약 표에는 개념과 유닛을 **함께** 싣되 번호로 구분한다(`[N]` vs `[U N]`).

**파트 1 — 학습 여정.** 이 주제를 어떤 순서로 훑고 왜 그 순서인지를 서술한다. 개념들이 어떻게 이어지는지, 실습형이면 참조 구현이 어떤 흐름으로 도는지를 텍스트 흐름도로 표현한다. **이 서술은 건조한 보고가 아니라 `explanation-principles.md`의 페르소나**(강의의 목소리)로 쓴다 — 다만 개요는 지도이므로 학습 문서만큼 깊이 파지는 않는다(예시 문장 구조를 복제하지 말고 주제마다 다르게 합성).

개념이 셋 이상이거나 선수 관계가 분기·합류하면 텍스트 흐름도만 두지 않고 **Mermaid 선수 관계·개념 지도**를 함께 넣는다. 노드는 개념·선행 학습을, 화살표는 "이 이해가 다음 이해를 가능하게 함"을 뜻해야 한다. 단순 목록을 그래프로 옮기는 것은 지도 역할을 하지 못한다.

**파트 2 — 개념 학습 포인트.** 추출·핵심/보조 분류·추천 점수·선행 학습·렌더링은 `concept-learning.md`의 'A. 통합 개요의 개념 파트'를 따른다.

**파트 3 — 구현 유닛.** 유닛 식별·관전 진입 유닛·장악 점수는 `implementation-mastery.md`의 'A. 통합 개요의 구현 유닛 파트'를 따른다. (순수 개념형 주제면 이 파트는 없다.)

요약 표 위에 **두 점수가 다른 축**임을 한 줄로 적는다:

```markdown
> 개념 포인트의 추천 점수('이해할 가치')와 구현 유닛의 장악 점수('직접 만들 가치')는 다른 질문에 답합니다. 한쪽의 높낮이를 다른 쪽과 견주지 마세요.

| # | 학습거리 | 종류 | 배지 | 점수 |
|--:|----------|:----:|:----:|:---:|
| **1** | 토큰 버킷 원리 | 개념 | 🔴 필독 | 88 |
| **U1** | 요청→소모→허용 조립 | 구현 | 🔴 직접 장악 | 90 |
```

## 학습 강도 (가볍게 ↔ 무겁게)

강도는 이분법이 아니라 **다이얼**이다. 아래 두 끝점 사이를 주제·요청에 맞춰 보간한다. 강도가 정하는 것은 *폭·의식(儀式)·산출물의 무게*이지 **설명의 깊이가 아니다** — 어느 강도에서도 다루기로 한 것은 메커니즘까지 도출한다(`explanation-principles.md`).

**가볍게 (빠른 심층 설명):**
- 점수 개요(overview.md)를 만들지 않는다. 짧은 섹션 지도를 채팅으로 제안하고 바로 설명에 들어간다.
- 1~3개 섹션으로 초점 있게. 폭을 좁히되 깊이는 유지.
- 평가·구현 장악은 기본 생략(학습자가 원하면 제공).
- 산출물은 주제 루트에 평평한 섹션 문서 몇 개.
- 프로필은 뚜렷한 지속적 특성이 관찰될 때만 가볍게 갱신.

**무겁게 (마스터):**
- 점수 통합 개요(개념 `[N]` + 실습형이면 구현 유닛 `[U N]`) → 학습자 선택.
- 고른 포인트마다 완결에 필요한 만큼 다중 섹션 심층.
- 이해도·장악 평가(질문·코드 과제·재구성·결함 주입 등).
- 실습형이면 구현 장악 트랙(참조 구현 → 관전 → 생성·검증)까지.
- 프로필 갱신 판단.

**중간:** 개요는 선택, 몇 개 섹션, 가벼운 평가 — 위 둘 사이. 요청이 어느 쪽인지 모호하면 한 줄로 확인하되, 주제가 작고 "빠르게"류면 가볍게, "배우자/마스터/직접 만들며"류면 무겁게를 기본으로 삼는다.

**강도가 흐름에 매핑되는 방식:** SKILL.md의 3단계에서 강도를 정하면 — 무겁게는 6단계(개요)→7(트랙)→8(평가)→9(프로필)을 모두 밟고, 가볍게는 6·8을 건너뛰고 7의 개념 학습만 짧게 돌린 뒤 9를 가볍게 판단한다.
