# master-crawler

**어떤 웹사이트든 분석해서 크롤링 전략을 세우고, 봇 탐지를 우회하는 방법론을 담은 스킬.** 특정 사이트에 종속되지 않는 범용 지식이며, 실전 시행착오에서 얻은 교훈을 정리했습니다.

## 어떤 문제를 푸는가

웹 크롤링은 "requests로 GET 한 번"으로 끝나는 경우가 드뭅니다. 403이 뜨고, JS 챌린지 페이지가 돌아오고, Cloudflare·Akamai 같은 보안 솔루션이 막고, TLS 지문이 안 맞아 차단됩니다. 이럴 때 무엇이 원인인지, 어떤 도구를 어떤 순서로 써야 하는지 감이 없으면 시간을 크게 낭비합니다.

master-crawler는 그 "막혔을 때 무엇을 봐야 하는가"를 체계화합니다. 정찰 → 보안 메커니즘 식별 → 전략 결정 → 구현 → 추출 → 트러블슈팅 → 유지보수까지 단계별로 정리해, 증상에 맞는 다음 수를 빠르게 찾게 합니다.

## 설계에서 가장 중요한 점

**이 스킬은 순서대로 밟는 절차가 아니라, 막혔을 때 꺼내 보는 참고서입니다.**

경험 기반 직관이 있으면 그것을 먼저 시도하는 게 더 빠릅니다. URL 변형이 떠오르면 바로 시도하고, 403이 TLS 문제 같으면 곧장 `curl_cffi`를 씁니다. 스킬은 그 직관적 시도가 모두 실패하고 원인을 모를 때, 또는 처음 보는 봇 탐지 증상이 나타날 때 참조하는 도구입니다. 이 "직관 우선, 참조는 필요할 때"라는 태도 자체를 지침 맨 앞에 못박아 두었습니다.

## 무엇을 다루는가 (Phase 구성)

| Phase | 내용 |
|-------|------|
| **1. 타겟 사이트 정찰** | 기술 스택 식별(SSR/CSR, 프레임워크), API 엔드포인트 수집, 인증 요구사항 분석, JS 챌린지 감지 |
| **2. 보안 메커니즘 식별** | 봇 탐지 시스템 식별 체크리스트, 방어 계층(5-Layer 모델), 브라우저 환경 탐지 인사이트 |
| **3. 크롤링 전략 결정** | 전략별 요약과, 실패했을 때의 대안 경로 |
| **4. 구현 가이드** | HTTP 직접 요청 → 하이브리드 → 네트워크 캡처, DrissionPage(CDP 직접 접근), 로그인 처리 |
| **5. 데이터 추출** | 추출 전략 우선순위, 복잡한 JSON 응답 다루기 |
| **6. 트러블슈팅** | 에러 코드별 방향, stealth·UC 모두 막힐 때, 갑자기 차단된 크롤러, TLS 지문 불일치 진단, **하지 않는 게 나은 것들(실패에서 얻은 교훈)** |
| **7. 장기 유지보수** | 유지보수 체크리스트, 토큰 라이프사이클, 보안 방식 변경 대응 |

## 쓰는 법

```
/master-crawler [대상 URL 또는 사이트 설명]
```

- "이 사이트 크롤링하려는데 403이 떠" → 증상에 맞는 Phase(정찰·트러블슈팅)를 짚어 원인과 다음 수를 제시합니다.
- "봇 탐지 우회 전략 세워줘" → 사이트 분석부터 전략·구현까지 안내합니다.

> ⚠️ 이 스킬은 인증된 테스트, 학습, 접근이 허용된 데이터 수집 같은 정당한 용도를 전제로 합니다.
